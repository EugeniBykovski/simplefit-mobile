# D. Domain gaps, API contract and route-registry parity (SF-159)

What the backend (`simplefit-api` `main` `3afa381`) has for each domain the
Fighter Mobile design needs, and what is missing. Evidence paths are relative
to the `simplefit-api` root unless a repository is named.

Backend conventions that apply to every domain: one global `users` row with
no role column (ADR 0009); contexts own authorization; foreign or unknown ids
answer `404 not_found` (no existence oracle); `client_request_id` idempotency
on creates; errors are `{"error":{code,message,details,request_id}}`
(ADR 0003); bearer `sfa_` access tokens with rotating `sfr_` refresh tokens
(ADR 0010).

### Error-code handling gaps (mobile)

The spec has no error-code enum: `Error.code` is a string; the 26 codes are in
the description. `src/shared/api/http/api-error.ts` treats `code` as a string
and mobile production code mostly branches on HTTP status.

| Code                            | Mobile references                      | Relevance                                        |
| ------------------------------- | -------------------------------------- | ------------------------------------------------ |
| `account_suspended`             | 0                                      | Suspended users (ST14, restricted-account guard) |
| `enrollment_required`           | 0                                      | Gym flows                                        |
| `step_up_required`              | 0                                      | Operators only today                             |
| `invitation_recipient_mismatch` | 0                                      | Coach and gym invitations                        |
| `revision_conflict`             | 0                                      | Any revisioned edit                              |
| `password_not_set`              | 0                                      | ST3 if password settings are built               |
| `invitation_unavailable`        | 0 in production (branches on HTTP 410) | FCI2                                             |
| `not_found`                     | 0 (branches on 404)                    | All reads                                        |

|                                          | `simplefit-platform`          | `simplefit-mobile`            |
| ---------------------------------------- | ----------------------------- | ----------------------------- |
| `docs/route-registry.json` sha256 prefix | `d658cd07125c71bf`            | `1089f3b6cb93dbba`            |

- The registry `$comment` says it is "kept identical" in both repos. It is
  not. The platform copy has six more web routes and screens

- There are no `mobile.*` differences between the copies.
- `docs/route-architecture.md` differs both ways (17 diff lines): mobile has
  the SF-80 `+native-intent` paragraph; the platform has the D-SA26/SF-117
  `D-WORKSPACE-NOT-IN-URL` text and the two new discrepancy rows.
- Mobile routes: 155 (154 `IMPLEMENTED`, 1 `DEFERRED` `mobile.sparring.find`).
  Checking each `production.file`: 42 real screens, 112 placeholders, 1 with no
  file. Registry `api[]`: 36 entries, 5 `IMPLEMENTED`, 31 `DEFERRED`.
- The registry `source.version` is `1791448557-b0b9`; the design read for this
  audit is `1794821244-6c73`.

Resyncing the two registries needs an SF ticket that updates both repositories
in one change (`docs/route-architecture.md` §15). See D-SF159-25.
