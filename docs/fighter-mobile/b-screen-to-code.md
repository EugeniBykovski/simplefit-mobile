# B. Screen-to-code map (SF-159)

Each fighter artboard against the mobile code that serves it, the API
operations it uses or would use, and the backend context that owns the rules.
Status vocabulary: [README](README.md#status-vocabulary). Route ids and paths:
[Artifact A](a-design-inventory.md).

- **Mobile Module** is the route file under `simplefit-mobile/src/app/` and the
  widget or feature it renders. "placeholder" means the route file is exactly
  `placeholderRoute("<id>")` (`src/widgets/feature-placeholder`).
- **API Operation** lists operationIds from `openapi/simplefit.api.json`
  (sha256 `69877335…ccfef`, 288 operations). "none in spec" means no operation
  exists. Ops marked _(unused)_ are generated in the client but not called by
  app code.
- **Backend Owner** is the `simplefit-api` context (`lib/simple_fit/**`) that
  owns the rule, or "none" when no context exists.

`verifyEmailLink`, `requestPasswordReset`, `confirmPasswordReset`,
`signInWithPassword`, `getMyPasswordStatus`, `changeMyPassword`,
`previewCoachInvitation`, `acceptCoachInvitation`, `declineCoachInvitation`,
`previewGymInvitation`, `getLegalDocument`, `getLegalDocumentVersion`,

`resolveGymInvitation`, `getMyGymInvitation`, `getMyGymMembership`,
`requestMyGymProduct`, `listMyGymProducts`, `listMyProductSubscriptions`,

The token-based coach and gym invitation ops are unused on mobile by design
(D-G22, D-MOBILE-FIGHTER-COACH-INVITATIONS): the native app never receives a
token.

## Implementation rules for new screens

- Replace the placeholder file; add the route id to the "real screens" list in
  `scripts/mobile-route-skeleton.test.js`; record any new discrepancy in the
  registry and in `docs/route-architecture.md`.
- Wrap plain generated request functions in hand-written `useMutation` hooks
  (pattern: `src/features/training-session-complete/model/complete-session.ts`).
  Orval generates `useQuery` hooks even for POST, so never call a generated
  mutation hook.
- Never call `fetch` outside `src/shared/api`.
