# A. Fighter Mobile design inventory (SF-159)

Every board on the Claude Design page `fighter-mobile` ("Fighter Mobile"), plus
the fighter-relevant boards that live on other pages. Scope, method and status
rules: [README](README.md).

- Source: artifact `JEsBg51MjX8KiHWEro8omY` (uuid
  `8b9af407-4197-4905-87b7-0ebf86bf35e7`), files downloaded at version
  `1794821244-6c73`. The file listing was read at `1794760506-29fa`; the
  version moved during the audit (another writer was active).
- 113 boards on the page: 4 flow sheets and 109 screen boards. Section counts:
  6 → 10, 7 → 13, 8 → 17, 9 → 17, 10 → 7, 11 → 3, 21 → 1, 23 → 9, 25 → 3,
  26 → 7, 27 → 12, 28 → 7, 30 → 3.
- **Size** is the board size on the canvas (`w×h` in `canvas.json`). Every
  screen board is 390 px wide, interactive, with a phone-frame radius of 44.
- **Route** is the `mobile.*` route id and path from `docs/route-registry.json`
  in this repository (mobile copy, sha256 `1089f3b6…`). Registry `IMPLEMENTED`
  only means a route file exists. The file kind (real screen or
  `placeholderRoute(...)`) was checked for every route.
- **States** are the board's `data-props` enums. "static" means the board
  declares only `$preview`: one fixed mock state, with no loading, empty,
  error or restricted design.
- **Status** follows the vocabulary in the README. A design `FUTURE` label is
  always kept. A placeholder route file is never `IMPLEMENTED`.
- All board content is mock data (Yauheni B., Warsaw Boxing Club, Coach Marek,
  etc.). Amounts and counts in the Notes column describe the mock, not product
  facts.
