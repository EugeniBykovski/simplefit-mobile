# E. Security and privacy (SF-159)

Who owns, reads and writes each kind of fighter data, and what the existing
rules say. Only rules with evidence in `simplefit-api` (ADRs, decision
registers, code) or in `simplefit-mobile` are stated as rules. Anything else
is marked **Decision needed** and listed in
[Artifact H](h-decisions-blockers.md). Design copy (for example S19's
visibility rows) is a design intent, not a rule.

No medical measurement is defined here. The backend has no health-data domain
or ADR; the only body data is the owner-only profile fields of ADR 0015.

## Cross-cutting rules

### Authorization

- Phoenix owns authorization; contexts receive the actor (`CLAUDE.md`).
  Client checks are UX only (mobile `CLAUDE.md` rule 1, 15).
- Foreign or unknown ids answer `404 not_found`; there is no existence oracle.
  Mobile treats 404 as "not available".
- Fighter routes render only when `resolveMyEntry` reports `FIGHTER`
  (`CapabilityGate`). Shared routes check the session only.

### Tenancy

- One global user; a person can be fighter, coach and gym staff at once
  (ADR 0009). Gym membership grants no gym permission and no workspace
  capability (`SimpleFit.Entry` rules).
- Gym roles never read fighter training, RPE, weight, notes, videos or
  messages (D-G06). This holds for every future fighter domain unless a new
  decision changes it.

### Consent

- Registration requires `terms` and `privacy`; history is append-only; a
  version bump only marks consent `current: false`. Re-consent is not built
  (L-13).
- Coach sharing needs the fighter's acceptance of a versioned disclosure,
  stored as legal evidence. Coaching activation is off by default
  (`COACHING_ACCESS_ENABLED`) and needs counsel sign-off (L-16).

### Retention

- No retention job exists. L-05..L-08 periods are proposals; D-SA18 keeps
  audit data until counsel decides. ST9's retention table is design copy.

### Cache isolation

- Refresh token only in `expo-secure-store`
  (`simplefit.session.refresh_token`, `WHEN_UNLOCKED_THIS_DEVICE_ONLY`);
  access token in memory; AsyncStorage holds only `locale` and `theme`.
- Query cache is cleared on sign-out and on a new sign-in. It is **not**
  cleared on a context switch (D-SF159-12). No persisted query cache.
- iOS sensitive HTTP cache module (`modules/sensitive-http-cache`). Android
  equivalent UNVERIFIED.

### Account lifecycle

- Suspension: reversible, operator-only, two-person rule proposed (D-SA17, not approved), audited;
  blocks every sign-in path, refresh and session use; lift does not restore
  sessions. No suspension email (D-SA29).
- Mobile does not handle `account_suspended`; restricted-account routes are
  placeholders with no navigation into them.
- Deletion, restore, export and appeal do not exist. L-09 defines the intended
  shape (neutral stub, no cross-user cascade). D-SA17 (PROPOSED, not approved) would exclude
  deletion and export from the MVP.
